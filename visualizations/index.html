Deep dive: authentication is not authorization

Authentication answers “who is making this request?” Authorization answers “may this identity perform this action on this specific object?” A signed-in user still needs an object-level permission check. Validate request data separately, and do not trust a client-supplied owner ID.

Deep dive: constrain authority, not just language

Prompts can guide behavior but cannot enforce access control. The server must validate the user, tool name, arguments, resource ownership, budget, and approval for every call. Deep dive: a pipeline is a risk-control system

Automated tests reduce known failure modes but do not prove a release is safe. Staged exposure and health checks provide new evidence after deployment. Deep dive: layer cache is ordered and content-sensitive

This teaching model assumes each changed layer invalidates all later layers. Docker cache behavior also depends on the instruction, build context, parent layer, and builder. A source change after dependency installation can reuse dependency layers; copying the whole repository before installing dependencies often makes ordinary code edits rebuild too much. A container adds a writable runtime layer on top of an image; image build and container startup are separate operations.

Deep dive: reachability is a chain of explicit controls

A simplified AWS design commonly places an internet-facing load balancer in public subnets, application tasks or instances in private subnets, and the database in private subnets. Security-group rules should allow only required source-to-destination flows. Use workload identity for AWS API access rather than embedding long-lived credentials in an image. Deep dive: configuration, state, plan, and drift

Terraform configuration declares desired resources; state maps those resources to objects Terraform manages. Planning refreshes and compares observed state with configuration, then proposes actions. Deep dive: idempotence and check-mode limits

An idempotent task converges a host toward the requested state; rerunning it after successful convergence should not report the same change again. Check mode predicts changes for supported modules but is not a universal proof that every task is side-effect-free or will succeed. Unreachable hosts are not the same as hosts whose tasks failed; inspect each result and handle partial fleet success deliberately.

Try: Run the drift scenario in check mode, then apply it, then apply it again. Explain why the second applying run should report the host as unchanged.

Deep dive: a merge commit preserves two parents

A fast-forward moves a branch pointer when its history is already an ancestor of the incoming branch. Diverged branches need a merge commit unless rebased; a textual conflict occurs when Git cannot combine overlapping edits automatically. Resolving a conflict means editing the file to the intended final content, removing markers, testing it, and committing the merge. Rebase rewrites commit identities and should be used with care on shared history.

Try: Compare the fast-forward and clean-merge graphs. For the conflict case, choose each resolution and explain why Git cannot decide which value is correct.

Deep dive: controllers reconcile; Services select ready endpoints

The Deployment controller creates or updates a ReplicaSet; the ReplicaSet attempts to maintain the requested pod count. A pod can exist but fail readiness, in which case it should not receive Service traffic. Image-pull errors prevent startup; repeated liveness failures can trigger restarts and back-off.
